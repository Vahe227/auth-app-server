# 📱 Auth App (Server)

## 📚 Description

In this project, I implemented user authentication using React Native on the client side and Node.js on the server side.
User-provided data is stored in a PostgreSQL database that I designed and configured.

The server is managed by the Express framework. Incoming requests are handled through Express APIs, and in some cases, the server also sends data back to the client using the same Express-based API structure.

Additionally, once a user logs in, the server remembers the user for 30 days, meaning the user does not need to log in again each time they open the application. This functionality is implemented using JWT (JSON Web Token) — the server identifies users through secure tokens generated by JWT.

The project also utilizes the dotenv library to manage environment variables, ensuring better stability and security across the application.

To make the server more efficient and responsive, I used the Cluster module, which allows handling incoming requests across all CPU cores instead of a single one. As a result, the server can process multiple requests simultaneously, improving its performance and scalability.

## 🛠️ Key Technologies

* **Node JS And Express** - The powerful backend of the application is built on Node.js, leveraging the Express.js framework for creating API endpoints and efficiently handling requests.
* **PostgreSQL** - The database is built with PostgreSQL, one of the most powerful and reliable database management systems. It allows importing and exporting data efficiently and provides full interaction capabilities through the SQL language.
* **JWT** - It is a data exchange format primarily used for user authentication and authorization. It provides a text-based token that is divided into three parts: Header, Payload, and Signature.
* **Dotenv** - It allows you to manage environment variables when working with Node.js.
Environment variables are typically stored in .env files, keeping sensitive configuration data out of the codebase. For example, database credentials such as port, host, password, and other sensitive information can be securely stored using this method.
* **OS** - This library allows you to interact with the operating system through code. It provides functionality to retrieve system information, delete certain data, and perform various other operations.
* **Cluster** - The Cluster module in Node.js enables the use of all CPU cores by creating multiple processes (workers) that can handle the same server concurrently.

## 🏗️ Modular Architecture

The project is built according to the principles of modular architecture, significantly improving the readability, understandability, and extensibility of the code. The code base is divided into two main logical parts (modules), each of which is responsible for a specific functionality, contributing to clean code and easy maintenance.

* **`CheckersJS`** - This section contains JavaScript and Node.js functions responsible for performing various validation and verification tasks within the project.
* **`checkTokenTime.js`** - This section checks the user’s token expiration.
If the token has expired, it is deleted from the database; otherwise, everything continues to function normally. It’s important to note that when a token expires, it throws an error, which is why this logic is wrapped inside a try-catch block for proper error handling.
* **`DataBase`** - This section contains all database-related functions responsible for inserting and retrieving data from the database. It also includes the core database configuration and management code, which handles the connection and interaction with the PostgreSQL database.
* **`DataBase/Actions`** - This section contains various validation and verification functions, such as those used for checking user login credentials and other related operations. 
* **`DataBase/Actions/checkIsUserLogined.js`** - This file is responsible for checking whether the user is already logged in. If the user’s token has not expired, it means their 30-day session is still valid, allowing them to continue using the application without logging in again. 
* **`DataBase/Actions/checkLoginData.js`** - This file is responsible for verifying the user’s login credentials.
It compares the data provided during login with the information stored during registration.
If the credentials match and everything is valid, the user is successfully authenticated and granted access to their account.
* **`DataBase/Deletes`** - This section contains functions responsible for deleting specific data from the database when necessary.
* **`DataBase/Deletes/deleteToken.js`** -  This file is responsible for deleting expired tokens from the database to ensure that only valid user sessions are maintained.
* **`DataBase/Inserts`** - This section contains functions responsible for inserting data into the database, handling operations such as adding new users or saving application-related information.
* **`DataBase/Inserts/insertRegisterValues.js`** - This file is responsible for inserting user registration data into the database, ensuring that all information provided during the registration process is securely stored.
* **`DataBase/Inserts/insertToken.js`** - This file is responsible for storing the user’s token in the database. After a user successfully logs in, the functions in this file are executed to save and manage their authentication token. 
* **`DataBase/serverDataBase.sql`** - This file is responsible for managing the database. It contains all the tables along with their corresponding data and structure definitions. 
* **`.env.example`** - This section provides a sample .env file that you can use to configure and run the project on your own system.
* **`index.js`** - This file contains the main server code, which manages the entire server using Express APIs. It interacts with all other files responsible for various functionalities throughout the project. 
* **`package-lock.json`** - In a Node.js project, this is an automatically generated file that records the exact versions and dependencies of all installed npm packages, ensuring consistent installation across different environments.
* **`package.json`** - In a Node.js project, this file stores essential project information such as name, version, dependencies, scripts, and other configurations. It is used by npm to determine which packages are required for the project and how to run it.

## 🚀 Getting Started

### Prerequisites 👾

* [Node.js](https://nodejs.org/) (v14 or higher recommended)
* [npm](https://www.npmjs.com/) (comes with Node.js)
* [PostgreSQL](https://www.postgresql.org/download/) (v16.10 or higher recommended)
* [JWT](https://jwt.io) (v9.0.2 or higher recommended)
* [Dotenv](https://dotenv.org) (v17.2.3 or higher recommended)

### Running The Setup ⚙️

#### 🚀 Setup & Run Guide

1. Open the official website PostgreSQL Download (link: https://www.postgresql.org/download/)
2. Select your operating system (Windows, macOS, or Linux) and download the latest stable version.
3. During installation, create a primary account (username & password). It is recommended to remember or note these credentials, as they will be required in your .env file.
4. Verify that PostgreSQL is running and that you can access it via psql or pgAdmin.

#### 🚀 Preparing the .env file

1. In the root folder of your project (Server folder), create a file named .env.
2. Add the necessary environment variables for your database and server configuration, for example:
```env
DB_USER=%YOUR_USERNAME%
DB_HOST=%YOUR_DATABASE_HOST%
DB_DATABASE=%YOUR_DATABASE_NAME%
DB_PASSWORD=%YOUR_PASSWORD%
DB_PORT=%YOUR_DATABASE_PORT%
```
⚠️ Important: The .env file should not be committed to GitHub or any public repository to keep your credentials secure.

#### 🚀 Updating Dependencies & Running the Server

1. Open a terminal or CMD and navigate to your Server folder:

    ```bash
    cd path/to/Server
    ```

2. Install necessary Node.js packages (if not already installed):

    ```bash
    npm install
    ```
    This command installs all dependencies listed in package.json and creates the node_modules folder.

3. Start the server:

    Make sure your .env file is correctly configured.
    Run the server using:
    ```bash
    npm run server
    ```
4. Expected output:
    ```bash
    server runing on http://localhost:%THERE_IS_YOUR_SERVER_PORT%
    ```
